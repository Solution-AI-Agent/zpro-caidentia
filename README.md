# CAIDENTIA · D2S

데이터센터용 서버의 설계·BOM·검토·공급 확약·부분 선정을 연결한 로컬 검증 환경이다. 모든 기업·품목·가격·물량은 합성 자료다. 실제 Dell 데이터와 내부 정책은 포함하지 않는다.

AI Native는 개발팀의 작업 방식이다. 제품 내 모델 API 연계는 포함하지 않는다. 사용자가 추가로 선택한 AG-UI 명령 탐색은 정해진 명령 규칙으로 실행한다.

## 실행

Node.js 24 이상과 npm을 사용한다. 이 환경에서는 macOS ARM64에서 검증했다.

```sh
npm ci
npm run dev
```

화면: <http://localhost:5173> · API: <http://127.0.0.1:4310/api/health>

`npm run dev`는 로컬 PostgreSQL, API, Vite를 함께 시작한다. 자료는 `.data/postgres`에 보존한다. DB 접속 정보는 `.data/database.json`에 제한된 파일 권한으로 생성하며 저장소에 포함하지 않는다. 종료 후 같은 명령으로 재시작한다. 별도 DB를 쓰려면 `.env.example`을 참고한다.

## 확인할 흐름

새 데이터베이스의 시작 상태는 조달 충족 300대분, 선정 0대분이다. 재시작은 업무 상태를 초기화하지 않는다.

1. 통합 검토 계정으로 공급 대안 B의 기술·품질을 각각 승인한다. 검토 근거를 기록한다.
2. 구성을 승인한다. 공급 확약 확인 전까지 조달 충족은 300대분이다.
3. B의 확약 400개를 확인한다. 충족은 500대분이며 선정은 아직 0대분이다.
4. B의 타 프로젝트 배분을 100개로 지정한다. 충족은 450대분이다.
5. A 600개와 B 300개로 선정안을 만들고 결정 이력에서 승인한다. 선정 450대분과 부족 50대분을 함께 표시한다.
6. 각 공급사에 결과를 따로 게시한다. 공급사는 게시 전 내부 선정을 볼 수 없다. 게시 후 자사 물량·기준 구성·제안·단가를 확인한다.
7. 결과 게시 후 인계 기록을 생성하면 결정 근거 JSON을 내려받는다. 계약·발주·ERP 등록은 수행하지 않는다.

BOM 설정에서는 세 가지 양식의 원본 열, 추가 속성, 필수 항목, 단위 별칭, 표시 순서, 공급사 BOM 표의 공개 필드를 지정한다. CSV 또는 값으로 된 단일 시트 XLSX를 검증한 뒤 새 개정으로 발행한다. 원본 전체 BOM을 공급사에 전송하지 않는다.

## L5 BOM 뷰어

`BOM` 탭에서 `토폴로지 뷰`와 `트리 목록`을 전환한다. 토폴로지는 왼쪽 트리와 오른쪽 오브젝트를 함께 보여준다. 부모 영역이 자식을 감싸며 L1~L5의 포함 관계를 표시한다. 선택·경로·아래 상세가 동기화된다. 두 보기에서 같은 선택을 유지한다.

영역을 제자리에서 접거나 펼친다. 표시 깊이, 전체 보기, 선택 맞춤, 확대·축소, 미니맵을 제공한다. 단순 선택이나 접기·펼치기는 사용자의 확대율과 화면 위치를 초기화하지 않는다. 상위를 접어도 선택한 부품의 상세를 유지한다. 부품 가까이에서 상세와 연결된 공급사 협의를 연다.

품목·이름·사용 위치를 전체 검색한다. 트리 검색은 검색 항목의 상위 경로를 함께 보여준다. 수량은 상위 1개당 수량과 최상위 1개당 누적 소요량을 구분한다. 같은 품목이라도 사용 위치가 다르면 별도 항목으로 처리한다. 전원 모듈과 하위 항목은 연결된 공급 대안 검토로 이동한다.

모의 BOM은 연산·메모리, 전원, 스토리지, 냉각, 섀시의 33개 사용 위치로 구성했다. 영역은 논리적인 포함 관계이며 실제 CAD 배치나 크기가 아니다. 깊이는 데이터에서 계산한다. CSV·XLSX 발행 시 L6 이상, 순환, 중복 위치, 누락된 부모를 거부한다. 기존 열 매핑과 추가 속성 설정을 유지한다.

공급사에는 공개 요청과 허용 필드만 반환한다. 내부 계층이나 전체 BOM 수량을 추정해서 표시하지 않는다. 최대 10,000개 행의 계층을 한 번 조회한다. 토폴로지는 선택 경로를 우선해 최대 200개 오브젝트를 그리며, 나머지는 트리·검색에서 선택한다. 트리는 100개씩 추가 표시하고 표는 100개씩 나눈다. 일반 목록 API의 200개 페이지 조회도 유지한다.

공통 색상·간격·타이포그래피·레이아웃·상호작용 기준은 [DESIGN.md](DESIGN.md)에 유지한다. 실행 토큰은 `src/index.css`의 단일 `:root`이며 문서와 CSS의 일치 여부를 자동 검사한다. BOM 탭도 기존 프로젝트 제목·조달 현황·청록색 테마를 유지한다.

## 명령으로 탐색

상단 `D2S 챗` 버튼으로 오른쪽 채팅 드로워를 연다. `공급사 B 검토 열어줘`, `현재 대안 협의 열어줘`, `PSU-B 자료 보기`를 입력하고 Enter 또는 전송을 누른다. 권한이 있는 공급 대안의 관계도와 상세 패널을 함께 연다. 탐색으로 승인·수량·선정 상태는 바뀌지 않는다.

드로워를 닫았다가 다시 열면 현재 페이지의 대화를 유지한다. 작은 화면에서는 `업무 화면 보기`로 결과 화면을 연다. 새로고침·로그아웃 시 대화는 초기화되며 서버에 저장하지 않는다.

실제 AG-UI SDK와 SSE를 연결했다. 정해진 탐색 명령을 지원하며 모델 서비스나 API 키는 필요하지 않다. [지원 범위와 평가 기준](docs/ag-ui-navigation.ko.md)을 참고한다.

## 구현 경계

React·TypeScript, shadcn/ui, React Flow, Motion, TanStack Query를 사용한다. 서버는 NestJS, XState, PostgreSQL, REST·SSE로 구성한다. 필드 검증은 Zod·Ajv를 사용한다. 실제 의존성 버전은 `package-lock.json`에 고정한다.

상태 변경은 서버의 권한·버전·업무 조건을 통과해야 한다. 하나의 구매기업 포트폴리오 행을 잠가 선정과 공유 물량 배분을 원자적으로 처리한다. 현재 두 공급사·전원 대체 그룹 하나의 검증 모델이며 임의의 대규모 D2S 그래프 엔진은 아니다. 동일 규칙 모듈을 두 합성 기업에서 서로 다른 전압 조건으로 사용한다.

설계·품질 계정에는 가격과 자유 형식의 상업 협의·첨부 자료를 제공하지 않는다. 기술·품질 검토 근거는 별도 검토 기록으로 남긴다. 공급사에는 자사 협의의 응답만 반환한다. PostgreSQL RLS는 구매기업 간 격리를 추가로 적용한다.

## 검증과 빌드

```sh
npm run verify
npm audit --omit=dev
```

시험은 별도의 임시 DB에서 실행하며 실행 중인 업무 DB를 초기화하지 않는다. 재시작·중복 제출·동시 배분·RLS·공급사별 파일/SSE·권한 철회·백업 복원을 포함한다. 측정 결과는 `.data/validation/performance.json`에 저장한다.

상세 결과와 미검증 범위: [실행 검증 기록](docs/d2s-implementation-validation.ko.md).

## 백업과 복원

로컬 DB가 실행 중일 때 다음 명령으로 업무 자료와 계정 정보를 백업한다. 세션은 백업하지 않는다. 기존 파일은 덮어쓰지 않는다.

```sh
npm run backup -- export .data/d2s-backup.json
```

복원 대상에는 먼저 동일 스키마를 생성하고 모의 데이터를 생성하지 않는다. `MIGRATION_DATABASE_URL`로 해당 **빈 DB**를 지정한 환경에서 실행한다.

```sh
npm run backup -- restore .data/d2s-backup.json
```

하나라도 기존 자료가 있으면 복원을 거부한다. 복원 후 다시 로그인한다. 백업에는 업무 자료와 비밀번호 해시가 포함되므로 `.data` 안에서 보관한다. 클라우드 백업·보관 기간·재해 복구 정책은 실제 운영 환경을 정할 때 검증한다.
