기준일: 2026-10-09. 환경: macOS ARM64, Apple M3 Pro, Node.js 24.21.0, 로컬 PostgreSQL 18.4. 모든 업무 자료는 합성 자료다. 아래의 이전 화면 검증 기록은 당시 동작을 기록하며, 현재 BOM 화면은 ‘포함 관계 토폴로지와 공통 디자인’ 절을 기준으로 한다.

## 화면에서 확인한 사항

1440 × 1050 화면에서 관계도·상세 패널과 모의 부분 선정 흐름을 확인했다. 구매기업은 두 공급 대안을 본다. 공급사 B는 B의 노드·요청·협의만 보며 전체 목표 500대, A의 노드, 내부 선정 물량을 받지 않는다.

[명령 탐색 실행 화면](assets/ag-ui-navigation-v0.1.png)은 1440 × 1150에서 저장했다. 조달 충족 450대분·선정 450대분·부족 50대분과 B 선택을 보여준다.

- C14: 이전 버전 조회 응답을 지연했다. 타 프로젝트 배분 변경으로 최신 충족 수량이 450대분이 된 뒤, 이전 455대분 응답을 해제했다. 화면은 450대분을 유지했다.
- C15: 키보드로 대안을 선택했다. 변경 근거 창을 닫으면 실행 버튼으로 초점이 돌아왔다. 모션 감소 상태에서는 연결선 애니메이션이 없고 같은 수량과 행동을 제공했다.
- NAV-01: BOM 탭에서 `공급사 A 검토 열어줘`를 Enter로 제출했다. 관계도와 A의 검토 패널이 함께 선택되고 패널 제목에 초점이 이동했다.
- NAV-03: 공급사 B 화면의 탐색 예시는 B만 표시했다. A를 요청하면 공개할 수 있는 대안이 없다는 오류를 표시하고 B 선택을 유지했다.
- NAV-05: `선정 승인해줘`는 지원 명령 안내를 표시했다. 기존 A·협의 패널 선택을 유지했다.
- NAV-06: 모션 감소 상태에서도 B 명령 탐색과 패널 선택이 같았다. B를 선택한 상태에서 A 명령의 응답을 보류하고 취소했다. 요청은 한 번만 전송됐고 입력이 다시 활성화됐다. 보류한 응답을 해제한 뒤에도 B·검토 패널과 취소 안내를 유지했다.

실행 중 SDK 스키마 가져오기 경로와 완료 메시지 처리 오류를 수정했다. 취소 버튼이 제출 버튼으로 바뀌며 다시 제출되는 문제도 수정하고 지연 응답으로 재검증했다. 최종 형식·SDK 통신 시험이 통과했다. 개발 서버의 파일 갱신 중 일시적인 재시작 오류와 모듈 새로고침이 있었으며, 브라우저를 새로 연 후 현재 동작을 확인했다.

## 오른쪽 채팅 드로워 전환

사용자의 후속 요청으로 상단 입력창을 `D2S 챗` 버튼과 오른쪽 드로워로 바꿨다. 기존 AG-UI API와 공개 범위를 유지한다. `npm run verify`의 32개 시험과 빌드가 다시 통과했다.

1440 × 1050에서 명령·응답 말풍선, B 검토 → A 협의 전환, 배경 관계도 클릭, 현재 선택 표시, 지원하지 않는 명령의 오류, Escape와 열기 버튼의 초점 복귀, 닫기·다시 열기의 대화 보존을 확인했다. 드로워 폭을 반영한 후 관계도 노드가 잘리지 않는다.

1024 × 900에서는 드로워가 배경 위에 열리며 가로 넘침이 없었다. `업무 화면 보기`로 닫으면 상세 패널 제목에 초점이 이동했다. 대기 중인 A 탐색 응답을 보류하고 드로워를 닫은 뒤 해제했다. 요청은 한 번 전송됐으며 기존 B 선택과 취소 기록을 유지했다.

공급사 B로 다시 로그인하면 이전 대화가 비워지고 B의 명령 예시만 표시됐다. Shift+Enter는 줄바꿈을 만들었다. 조합 중 Enter 이벤트를 재현했을 때 전송하지 않았으며, 일반 Enter에서는 한 번 전송했다. 모션 감소 설정의 드로워 애니메이션 시간과 연결선 애니메이션 제거도 확인했다. 실제 운영체제별 한글 입력기 전체의 검증은 포함하지 않는다.

## L5 BOM과 이전 구성 맵 뷰어

후속 요청으로 BOM의 부모·사용 위치 관계를 L1~L5 계층으로 검증한다. 깊이는 원본 행의 순서나 품목 번호가 아닌 부모 관계에서 계산한다. L6 이상, 순환, 중복 위치, 누락된 부모는 발행을 차단한다. 세 가지 기존 매핑 양식은 같은 33개 사용 위치의 모의 BOM을 생성한다.

`npm run verify`가 통과했다. 자동 시험은 34개다. L5의 10,000개 항목 조회·매핑, 10,000단계 오류 입력의 비재귀 처리, L6 발행 거부와 기존 개정 보존, 같은 품목의 다른 사용 위치, 순서가 바뀐 원본, 수량 누적, 검색 경로, 공급사 계층 응답 제한을 확인했다. 한 파일에 여러 최상위 항목을 지원하며 각각을 L1으로 취급한다.

실제 브라우저에서 확인한 결과:

- 1485 × 1050: 전원 시스템 L2 → 전원 조립체 L3 → 전원 모듈 L4 → 전원 제어 보드 L5. 전체 경로와 현재 깊이를 표시했다. 제어 보드의 완제품 1개당 소요량은 2개였다.
- L5에서 트리 목록으로 바꿔도 선택과 경로를 유지했다. `MEM-DIE` 검색은 메모리 다이와 4개 상위 경로를 보여줬다. 이를 선택하고 구성 맵으로 전환하면 `1 × 16 × 8 × 2 = 256`개를 표시했다.
- 1024 × 900: 가로 넘침 없이 탐색했다. AG-UI 드로워의 `업무 화면 보기`는 선택한 BOM 제목으로 초점을 돌렸다.
- 1485 × 1050에서 AG-UI 드로워를 함께 열어도 BOM 영역과 드로워가 겹치거나 가로로 넘치지 않았다. `공급사 A 검토` 명령은 기존 관계도와 A 검토 패널로 이동했다.
- 공급사 B: 구성 맵과 트리 목록 모두 자사 공개 요청 1개, 수량 400개만 표시했다. 내부 R2·33개 항목·부모 경로·L5·A의 품목은 제공하지 않았다. 필드 제외는 API 시험으로 검증했다.

실행 중인 모의 프로젝트에는 R2를 정상 발행했다. R1의 10개 항목과 과거 선정 450대분 기록은 그대로 보존했다. 새 BOM 발행 규칙에 따라 기술·품질·구성 재검토가 필요하며, 현 조달 충족은 0대분으로 다시 계산됐다. 이 변경은 선정 취소나 공급 확약 철회가 아니다. 새 DB는 처음부터 L5 모의 BOM으로 시작한다.

[전체 구성 맵](assets/bom-viewer-overview-v0.1.png) · [L4 모듈과 L5 부품](assets/bom-viewer-l5-v0.1.png). 시각화는 논리적 포함 관계를 표현한다. 실제 CAD·3D 형상, 물리적 배치, 원가 비례 면적, 대규모 브라우저 부하와 독립 사용자 이해도 시험은 포함하지 않는다.

## 포함 관계 토폴로지와 공통 디자인

2026-10-09 사용자 승인 방향을 적용했다. 왼쪽 L1~L5 트리와 오른쪽 2D 오브젝트 토폴로지를 함께 표시한다. 부모 영역이 자식을 감싸며, 트리·오브젝트·경로·아래 상세가 같은 사용 위치를 선택한다. 기존 React Flow를 사용한다. 별도 3D 구현과 Three.js 의존성은 제거했다.

BOM 전용 어두운 테마와 프로젝트 제목·조달 현황을 숨기던 CSS를 제거했다. 공통 청록색 팔레트와 work-surface를 사용한다. [DESIGN.md](../DESIGN.md)에 색상·간격·타이포그래피·모션·레이아웃 기준을 기록했다. `tests/design.test.ts`는 문서의 토큰 표와 단일 CSS `:root` 값을 대조한다. `AGENTS.md`는 이후 UI 변경 시 두 파일을 함께 유지하도록 안내한다.

`tests/bom-topology.test.ts`는 부모 영역 내부 배치, 형제 간 비겹침, 부모 우선 순서, 같은 품목의 다른 사용 위치, 원본 불변성, 표시 수 제한, 선택 경로 우선 확보와 접기·깊이 제한을 확인한다. 기존 권한·업무·BOM 시험과 함께 37개가 통과했다.

실제 브라우저에서 확인한 결과:

- 관계도와 BOM의 프로젝트 제목·조달 현황·공통 탭 위치 및 primary 색상이 같았다. BOM 콘텐츠만 전체 작업 폭을 사용한다.
- L5 전원 제어 보드·냉각 팬 선택이 트리·상세에 동기화됐다. 확대 후 선택하거나 상위 전원 시스템을 접어도 확대율과 화면 위치를 유지했다. 숨겨진 부품의 상세도 유지했다.
- `MEM-DIE` 검색은 메모리 다이와 4개 상위 경로를 표시했다. 선택한 항목의 최상위 1개당 소요량은 `1 × 16 × 8 × 2 = 256 EA`였다. 트리 목록과 토폴로지 사이에서 선택을 유지했다.
- 표시 깊이 L2에서는 최상위와 L2의 6개 영역만 그렸다. 이후 검색에서 L5 냉각 팬을 선택하면 경로를 펼치고 표시 깊이를 L5로 복원했다.
- 트리에서 ArrowDown으로 냉각 팬 다음의 전원 커넥터를 선택하고 초점을 이동했다. 상위를 접어 선택 행이 숨겨져도 트리에 Tab 진입점이 남았다. 앱의 모션 줄이기에서는 노드·선택 전환 시간이 0.01ms였다.
- 1485 × 1150, 1024 × 900, 768 × 900에서 가로 넘침이 없었다. 우측 챗은 넓은 화면에서 폭을 나누고 좁은 화면에서 겹쳐 열렸다. `업무 화면 보기`는 BOM 상세 제목으로 초점을 돌렸다. 640 × 900에서는 트리와 뷰어가 세로로 쌓이며 뷰어 높이 480px을 유지했다.
- 공급사 B의 토폴로지와 표는 자사 공개 요청 1개와 수량 400개만 표시했다. 내부 L5·33개 사용 위치·상위 경로·A 품목은 표시하지 않았다.

[현재 BOM 화면](assets/bom-topology-v0.2.png). 상자 크기는 실제 치수·수량·가격을 뜻하지 않는다. 토폴로지는 최대 200개를 표시하고 선택 경로를 우선한다. 트리는 100개씩 추가 표시하고 표는 100개씩 나눈다. 10,000개 입력의 API 조회와 브라우저에서 전체 10,000개 오브젝트를 동시에 그리는 성능은 서로 다른 검증 범위다. 후자는 수행하지 않았다.

로컬의 짧은 표본이다. 30,000개 관계 탐색, 200개 노드·400개 간선의 브라우저 렌더링, 장시간 부하, 고객망 지연, SSE 전달 지연의 백분위는 측정하지 않았다. 이 결과로 운영 성능 기준 전체의 통과를 판정하지 않는다.

## 빌드와 의존성

운영 의존성 검사 `npm audit --omit=dev`는 알려진 취약점 0건이다. 개발 의존성을 포함한 검사에는 high 7개 패키지가 남아 있다. 공통 원인은 shadcn CLI의 `fast-glob → micromatch → braces` 경로에 보고된 중첩 패턴 처리 취약점이다. 감사 도구의 제안은 shadcn 1.0.0으로의 주요 버전 변경이므로 자동 적용하지 않았다. 원본은 `.data/validation/audit.json`이다.

생성된 주 JavaScript 묶음은 963.32 kB, gzip 300.43 kB다. 명령 사용 시 불러오는 묶음은 258.67 kB, gzip 57.12 kB다. 빌드는 성공했으며 주 묶음이 500 kB를 초과한다는 경고가 있다. 운영 배포 전 화면 단위 분할과 실제 접속 환경의 초기 로딩 시간을 확인해야 한다.

## 남은 검증과 구현 경계

현재 UI 관계도는 구매기업 기준 6개 노드의 전원 대체 그룹 모델이다. BOM 뷰어는 최대 10,000개 행의 계층을 조회하고 토폴로지 최대 200개, 트리 100개씩 추가, 표 100개씩 표시한다. 일반 목록 API는 200개 페이지 조회를 유지한다. 데이터베이스는 구매기업 포트폴리오 행을 잠가 물량 변경을 처리한다. 일반적인 대규모 D2S 그래프, 여러 프로젝트의 최적 배분, 복잡한 서버 전체 구성 검증은 후속 작업이다.

Extension 1.0.0과 1.1.0은 버전 영향 검증용이며 같은 호환 검사 알고리즘을 사용한다. 외부 패키지 설치·샌드박스·마켓플레이스·실제 두 번째 고객 재사용은 검증하지 않았다. 실제 전기·열·인증 적합성은 합성 규칙으로 판정할 수 없다.

초기 협의는 구매기업과 공급사 한 곳씩 진행한다. 설계·품질 계정에는 가격과 자유 형식의 상업 협의·첨부 자료를 제공하지 않는다. 기술·품질 검토 근거는 별도 기록한다. 세부 필드·문서 분류 정책은 실제 고객과 확인해야 한다.

1차 범위 전체의 합격 판정에는 관리자가 세 BOM 양식을 설정하는 관찰 기록, 두 공급사와 각각 두 회차 이상의 종단간 협의 기록, R1·R2 선정 관계 추적 사례, 실패·재연결 과업의 추가 화면 기록이 필요하다. 자동 시험의 개별 통과를 이 모든 산출물 증거로 대체하지 않는다.

실제 Dell 담당자·BOM·견적, 기존 업무 시간 기준선, 독립 사용자 과업 시험은 미확보다. 화면 이동 감소와 이해 속도의 목표는 아직 측정하지 않았다. 기업 인증·운영 권한 정책·클라우드 복구, 실제 경매·역경매, PLM·ERP 연계는 현재 구현 범위 밖이다.
